# ChangeLog

## 0.4.0 (10/27/2026)

### Breaking changes

#### Removed StrawberryShake types

The typed GraphQL client is now generated by the SDK generator instead of StrawberryShake. Every type that `OrderGraphQLClient` accepts or returns keeps its name, namespace (`EBay.OrderManagement.Generated.GraphQL`) and members. The result interfaces, result classes, input classes and enums are unchanged. Only StrawberryShake's own plumbing is no longer public:

- `IOrderManagementGraphQLClient`, `OrderManagementGraphQLClient`, and the per-operation `I{Operation}Query`, `I{Operation}Mutation`, `{Operation}Query`, `{Operation}Mutation` and `{Operation}{Kind}Document` types
- `AddOrderManagementGraphQLClient` (namespace `Microsoft.Extensions.DependencyInjection`). Use `AddOrderManagementSdk`.
- the `EBay.OrderManagement.Generated.GraphQL.State` namespace, `{Enum}Serializer` and `{Input}InputValueFormatter`
- input classes no longer implement `State.I{Input}Info`

### Added

- Target framework `net472` (.NET Framework 4.7.2).
- Typed GraphQL operations work with the standalone `new OrderManagementClient(config)` constructor. Before, they needed dependency injection.

### Changed

- `GraphQL.ExecuteRawUnsafeAsync` under dependency injection now throws `UnauthorizedException` for HTTP 401 and `GraphQLException` for other non-2xx responses. It used to throw a raw `HttpRequestException`. Standalone mode already behaved this way.
- On .NET Framework the SDK's HttpClients allow 64 connections per host instead of the `ServicePointManager` default of 2.
- `OrderManagementConfiguration.HttpTimeout` and `RequestOptions.Headers` have `set` accessors instead of `init`, so projects compiled with C# 7.3 can assign them. Existing source compiles unchanged; recompile code that was built against 0.3.0.

### Fixed

- `OrderInquiryAsync` no longer throws `GraphQLException` ("Value cannot be null.") when `sellerAvailableActions.secondaryActions` contains an `OrderInquiryReferralAction`.

## 0.3.0 (09/25/2026)
